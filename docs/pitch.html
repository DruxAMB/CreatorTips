The problem

Tipping a creator on-chain means asking for a 42-character address — then hoping there's no typo. A claimed human handle resolves to the wallet on-chain: supporters type @name and the contract handles the rest.

What CreatorTips is

Claimable handles. One lowercase handle per wallet (2–32 chars, a-z0-9._-), enforced on-chain — first come, first served.
Hard-coded split. Every tipHandle payment divides 95% creator / 5% treasury in contract code — no backend could skim it.
Public resolution. Anyone can check resolveHandle before sending — the mapping is transparent and composable.
Permanently addressed. UUPS + ERC1967 proxy: the implementation can be upgraded while the address integrators reference never changes.

Why it fits BOT Chain

  • Payments UX primitive — handle-based payouts are infrastructure the whole AI/agent ecosystem can reuse (tip an agent's owner, pay a service).
  • Real transaction surface — every claim and tip is a user-paid mainnet transaction moving real BOT.
  • Sustainable protocol fee — the 5% treasury split is recurring, honest protocol revenue from actual utility.
  • Composable — other contracts can resolve handles on-chain; AgentID and badge/tipping flows can share the namespace.

Roadmap

  • Handle release/transfer via owner-signed messages.
  • Event indexer for a full-history leaderboard beyond the 30-event feed.
  • AgentID integration — tip a registered agent by its on-chain identity.
